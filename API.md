# API магазина цифровых товаров

## Общие сведения

Базовый адрес при локальном запуске:

```text
http://localhost:8080/api
```

Все тела запросов и ответов передаются в формате JSON. Для операций создания, изменения и удаления требуется токен доступа:

```http
Authorization: Bearer <accessToken>
Content-Type: application/json
```

Данные хранятся в памяти сервера и восстанавливаются после его перезапуска или запроса `POST /api/__reset`.

## Учётные записи

| Роль | Логин | Пароль | Возможности |
|---|---|---|---|
| Администратор | `admin` | `admin123` | Все операции, включая восстановление и окончательное удаление |
| Менеджер | `manager` | `manager123` | Просмотр, создание, изменение и мягкое удаление |

## Служебные адреса

### Проверка состояния сервера

```http
GET /__health
```

Ответ `200 OK`:

```json
{
  "status": "ok",
  "time": "2026-10-05T10:00:00.000Z"
}
```

### Сброс данных

```http
POST /__reset
```

### Имитация задержки и ошибки

К любому запросу можно добавить один из параметров:

```text
?__delay=1500
?__fail=500
```

## Авторизация

### Вход

```http
POST /auth/login
```

Тело запроса:

```json

  "password": "admin123"
}
```

```json
{
  "accessToken": "...",
  "refreshToken": "...",

    "name": "Администратор",

```




## Общий формат списка

Списки возвращаются в следующем формате:

```json
{
  "items": [],
  "page": 1,
  "size": 10,
  "total": 20,
  "totalPages": 2
}
```

Общие параметры списков:

| Параметр | Описание |
|---|---|
| `search` | Поиск по текстовым полям |
| `sort` | Поле и направление, например `name,asc` |
| `page` | Номер страницы, начиная с 1 |
| `size` | Размер страницы от 1 до 100 |
| `includeDeleted` | При значении `true` включает удалённые записи |

## Общие операции CRUD

Для каждого ресурса используются одинаковые основные адреса:

| Метод и адрес | Назначение | Доступ |
|---|---|---|
| `GET /{resource}` | Получить список | Без авторизации |
| `GET /{resource}/{id}` | Получить одну запись | Без авторизации |
| `POST /{resource}` | Создать запись | Менеджер или администратор |
| `PUT /{resource}/{id}` | Полностью изменить запись | Менеджер или администратор |
| `PATCH /{resource}/{id}` | Частично изменить запись | Менеджер или администратор |
| `DELETE /{resource}/{id}` | Выполнить мягкое удаление | Менеджер или администратор |
| `POST /{resource}/{id}/restore` | Восстановить запись | Администратор |
| `DELETE /{resource}/{id}?hard=true` | Удалить окончательно | Администратор |
| `POST /{resource}/bulk-delete` | Выполнить мягкое удаление нескольких записей | Менеджер или администратор |

Тело запроса множественного удаления:

```json
{
  "ids": [1, 2, 3]
}
```

## Товары

Ресурс:

```text
/products
```

Дополнительные параметры списка:

| Параметр | Описание |
|---|---|
| `type` | `gameKey` или `aiSubscription` |
| `brandId` | Код бренда |
| `platformId` | Код платформы |
| `categoryId` | Код категории |
| `priceFrom` | Минимальная стоимость |
| `priceTo` | Максимальная стоимость |

Структура товара:

```json
{
  "id": 1,
  "name": "Counter-Strike 2 Prime",
  "sku": "CS2-RU",
  "description": "Цифровой товар",
  "type": "gameKey",
  "brandId": 1,
  "price": 1490,
  "platformId": 1,
  "categoryIds": [1, 3],
  "region": "Россия",
  "durationMonths": null,
  "createdAt": "2026-10-05T10:00:00.000Z",
  "deletedAt": null
}
```

Правила:

- `name` и `sku` обязательны;
- `sku` должен быть уникальным;
- `price` является положительным целым числом;
- бренд, платформа и категории должны существовать;
- для подписки обязательно поле `durationMonths`.

## Пользователи магазина

В интерфейсе сущность называется «Пользователи». В API используется название `customers`, чтобы покупатели не смешивались со служебными учётными записями авторизации.

Ресурс:

```text
/customers
```

```json
{
  "id": 1,
  "name": "Алексей Смирнов",
  "email": "alex@example.com",
  "nickname": "alex_play",
  "createdAt": "2026-10-05T10:00:00.000Z",
  "deletedAt": null
}
```

Почта и никнейм должны быть уникальными.

## Оформление корзины

```http
POST /carts/{id}/checkout
```

Операция создаёт заказ и элементы заказа, сохраняет текущие цены товаров, вычисляет общую стоимость и очищает корзину.

Ответ `201 Created`:

```json
{
  "id": 1,
  "customerId": 1,
  "status": "new",
  "totalPrice": 3980,
  "orderedAt": "2026-10-05T10:00:00.000Z",
  "items": [
    {
      "id": 1,
      "orderId": 1,
      "productId": 1,
      "quantity": 1,
      "price": 1490
    },
    {
      "id": 2,
      "orderId": 1,
      "productId": 11,
      "quantity": 1,
      "price": 2490
    }
  ]
}
```

При попытке оформить пустую корзину возвращается `409 Conflict`.

## Ошибки

Обычная ошибка:

```json
{
  "message": "Запись не найдена"
}
```

Ошибка проверки полей:

```json
{
  "message": "Ошибка валидации",
  "errors": {
    "sku": "Товар с таким артикулом уже существует"
  }
}
```

| Код | Значение |
|---|---|
| `400` | Некорректный JSON |
| `401` | Пользователь не выполнил вход или токен недействителен |
| `403` | Недостаточно прав |
| `404` | Запись или адрес не найдены |
| `405` | HTTP-метод не поддерживается |
| `409` | Операция нарушает связи или состояние данных |
| `422` | Данные не прошли серверную валидацию |
| `500` | Внутренняя ошибка сервера |

Окончательное удаление записи, которая используется в связанных данных, возвращает `409 Conflict`.
